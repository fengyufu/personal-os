## 一、要做的模块

### 1. `app/services.py`：抽出共享业务逻辑
- 把上班 / 下班打卡逻辑从 `api.py` 抽到这里（`clock_in(conn, plan)`、`clock_out(conn, summary)`、`get_open_session(conn)`），`api.py` 和托盘都调用它，避免两套逻辑。
- 注意保留现有行为：进行中的 session 不按日期过滤（支持跨零点下班），已有测试必须全部通过。

### 2. `app/screenshot.py`：截图
- 用 `mss` 截**所有显示器合并的整张图**（`monitors[0]`），用 Pillow 存为 JPEG，质量取 `screenshot.quality`。
- 保存到 `cfg.screenshots_dir / "YYYY-MM-DD" / "HHMMSS.jpg"`，数据库 `screenshots.path` 存**相对 screenshots_dir 的路径**（用 `/` 分隔，前端 `/shots/<path>` 直接能用）。
- 以下情况**跳过**，并返回跳过原因（写日志，不写库）：
  1. 当前没有进行中的打卡；
  2. 截图暂停中（见第 5 点）；
  3. 锁屏或屏保中（Windows：`ctypes` 调 `user32.OpenInputDesktop`/`GetForegroundWindow`，前台窗口为空或属于 `LockApp.exe` 视为锁屏）；
  4. 前台窗口标题包含 `screenshot.exclude_apps` 里任一关键词（隐私）；
  5. 画面和上一张几乎一样：缩成 32×32 灰度图做平均哈希，汉明距离 ≤ 3 视为无变化。
- 提供 `capture(conn, cfg, force=False)`：`force=True` 时忽略第 2、5 条（给「立即截图」用），但**锁屏和隐私窗口仍然跳过**。
- 平台相关代码集中在一个小函数里；非 Windows 下锁屏 / 前台窗口检测返回「未知=不跳过」，保证 Linux 上能跑测试。
- `cleanup(conn, cfg)`：删除超过 `keep_days` 天的截图文件、数据库记录和空目录。

### 3. `app/reminders.py`：提醒规则（纯函数，便于测试）
`due_reminders(conn, cfg, now) -> list[Reminder]`，`Reminder` 含 `key`（去重用）、`title`、`body`。规则：
| 规则 | 触发条件 | key 示例 |
|---|---|---|
| 任务到点 | 未完成任务 `due_date + due_time` 落在 `(now-2min, now]` | `task:12:2026-11-25T10:00` |
| 该上班了 | 工作日，`now >= work.clock_in_remind`，今天还没打卡，且在 12:00 前 | `clockin:2026-11-25` |
| 工作太久 | 进行中 session 已超过 `work.max_hours` 小时 | `overtime:<session_id>` |
| 上班早报 | 打卡后 1 分钟内：列出逾期 + 今天到期任务数和前 3 个标题 | `morning:<session_id>` |
| 项目停滞 | active 项目超过 3 天没日志（或创建后 3 天没日志），每天上午 10 点后提醒一次 | `stale:<project_id>:2026-11-25` |

- 调用方用 `reminders_sent` 表去重：key 已存在就不再发。
- `now` 一律由参数传入，函数内部不要调 `datetime.now()`。

### 4. `app/notify.py`：系统通知
- Windows 用 `win11toast`，点击通知打开 `http://127.0.0.1:<port>/`。
- 非 Windows 或导入失败时退化为 `logging.info`，**任何异常都不能让调度器崩掉**。

### 5. `app/scheduler.py`：调度
- 用 APScheduler `BackgroundScheduler`，**每分钟**跑一次 `tick()`：
  - 有进行中的打卡，且距最近一张截图 ≥ `interval_minutes` → `capture()`；
  - 计算提醒，去重后发通知并写 `reminders_sent`。
- 每天 03:00 跑 `cleanup()`。
- 「暂停截图」用内存变量 `paused_until`，不需要入库。
- 每个任务用 try/except 包住并记日志；调度器只在 `main.py` 里启动，**`create_app()` 不启动调度器**（测试里不能真的截图）。

### 6. `app/tray.py`：托盘图标（pystray）
- 菜单：打开面板 / 上班打卡 / 下班打卡 / 立即截图 / 暂停截图 1 小时（再点恢复） / 退出。
- 图标用 Pillow 代码画一个简单圆点：上班中为绿色，未上班为灰色，每分钟刷新一次状态。
- 上班 / 下班从托盘点时，弹简单输入框（`tkinter.simpledialog`）填计划 / 总结，可留空。
- 托盘只在 Windows 上启用。

### 7. `app/main.py`：启动顺序
- 启动参数：`--no-tray`、`--no-browser`。
- 端口已被占用时视为已经在运行：直接打开浏览器面板然后退出（单实例）。
- uvicorn 跑在后台线程，托盘跑在主线程；退出时依次停止调度器和服务。
- 默认启动后自动打开浏览器面板。

### 8. 新增 API（写进 `api.py`，前端顺手接上）
```
GET  /api/scheduler/status     {running, screenshot_paused_until, last_shot_at, next_shot_in_minutes}
POST /api/screenshots/capture  立即截图，返回新记录或跳过原因
POST /api/screenshots/pause    {minutes}，minutes=0 表示恢复
```
前端：侧边栏打卡区下方显示「下次截图 xx 分钟后」和「暂停 / 恢复截图」按钮；「打卡记录」页的截图点开看大图（简单的 `<dialog>` 即可）。
调度器状态通过 `app.state.scheduler` 传给 API；测试中没有调度器时返回 `running: false`。
